The 6 Problems with Model-Driven Workflows

Bloated Context

300-600 lines of instructions dumped at once. By Phase 8, Phase 1 is compressed or forgotten.

Starts strong, then operates on vibes.

Hallucinated Completion

“Design verified” after checking 2 of 15 components. “Build passes” without running it.

You believe “done” — bugs surface in QA.

Skipped Phases

12 phases = 12 chances to skip. The model silently walks around your safety net.

Phases designed to catch problems get skipped.

Assumption Cascade

Ambiguity in Phase 2? Model assumes instead of asking. By Phase 6, three assumptions stack.

Code works but solves the wrong problem.

Context Window Decay

Long conversations compress earlier messages. A 50-line rule becomes one sentence.

First phase excellent, last phase sloppy.

Mindset Drift

Rules about how to think are followed when fresh, ignored when not.

Patches first, asks never. Declares done early.
Why more rules don't fix it: The model is both the worker and the supervisor.
Skip step → Add rule → 300→600 lines → Compressed → Drift → ↺ repeat

How Commands Work Today

A workflow lives as one massive skill file or CLAUDE.md. The model receives everything in a single context dump.

Forge: Focused Steps from YAML
workflows/build-feature.yamlphases: gather: steps: [download-srs, download-design, read-spec] explore: steps: [explore-spec] gate: human plan: steps: [design-discovery, write-plan] gate: human build-backend: steps: [schema, domain, persistence, api] verify: steps: [design-verify, srs-audit, tests] gate: human ~40 lines — Forge reads this, model never sees it
steps/explore-spec.yamlprompt: | Read the spec at {{spec_path}}. Identify ambiguities, missing rules, and questions for the BA. Output as JSON. evidence: - output_contains: "findings" inject: [spec_path, srs_path] ~15 lines — ALL the model sees for this step
steps/build-domain.yamlprompt: | Build the domain layer for {{feature}}. Schema: {{schema_output}} evidence: - files_exist: ["**/*aggregate*", "**/*mapper*"] - command: "yarn build" inject: [plan_path, schema_output] ~20 lines — fresh session, only relevant context

Each step: 10-30 lines. No phase-skipping. Evidence checked by Forge.

What We've Built So Far

We didn't jump straight to Forge. Each iteration taught us what the model can and can't be trusted to do.

Done Stage 1: Text-Only Skills

Skill files are pure markdown: "Phase 1: do X. Phase 2: do Y." The model reads the whole thing and we hope it follows every step.

Problem: The model treats it as a suggestion. Skips phases, self-reports completion, drifts in long conversations.

# /build-feature skill (594 lines) Phase 0a: Download SRS Phase 0b: Download design Phase 1: Explore spec, produce findings Phase 2: Write plan, get approval Phase 3: Design discovery Phase 4: Build backend ... 8 more phases, all in one blob
Done Stage 2: Tool Calls as Scripts

Key insight: skills shouldn't be just text. We converted deterministic operations (fetch SRS, download design, run validation) into actual tool calls wrapped in scripts.

The LLM's job shifts from "follow these instructions" to analyze context and pass the right arguments to a script that executes deterministically.

# Instead of: "download the SRS document" # The skill calls a script: fetch-srs --doc-id ${analyzed_doc_id} fetch-design --url ${design_url} validate --app server # LLM analyzes which doc, which URL # Script handles the actual download # No hallucinated "I downloaded it"
Next Stage 3: Forge Orchestrator

Take the script pattern to its conclusion: every step is a script, every transition is enforced by a state machine, every output is evidence-checked.

The LLM never sees the full workflow. It gets one focused prompt, does one thing, and Forge decides what's next.

# Forge reads the YAML, not the LLM: phase: build-backend step: domain prompt: "Build aggregate for {{feature}}" inject: [plan_path, schema_output] evidence: - files_exist: ["*aggregate*"] - command: "yarn build" on_fail: retry(3)
The evolution: From hoping the model follows text → to deterministic execution.
Text blob → LLM + scripts → Forge

5 Core Principles

1

LLM Never Sees Full Workflow

Each step gets 10-30 lines. Can't skip Phase 3 — doesn't know Phase 4 exists.

2

Evidence, Not Self-Report

Forge runs yarn build itself. File exists or doesn't. Command passes or fails.

3

Fresh Session Per Step

No accumulated context. Only explicitly injected data carries forward.

4

No AI in Orchestration

Rust binary. Cannot be convinced to skip. Cannot hallucinate a file exists.

5

Human Gates

At spec, plan, design, SRS audit — the tool stops. Only the human can approve.

“The problem was never that models are bad at coding. The problem is that we asked them to be both the worker and the project manager.”

Forge gives project management back to deterministic code and lets the model do what it does best: solve one clear problem at a time.
